A · Key Terms — definitions are printed; you fill in the rest

Domain modelA picture of the problem the client described, drawn as classes. It answers “what does the system have to know about?” — never “how will the machine do it”.
Conceptual classA candidate box. It becomes a real class only if it has identity and a sentence in a specification behind it. Otherwise it is a guess.
Analysis modelThe W06–W09 model of the problem. No technology, no framework, no language. It changes when the requirements change.
Design class diagram (DCD)The W10 model of the solution. Its names end in Service, Controller, Repository, DTO. If your diagram would still make sense in another language, it is not yet a DCD.
Entity classStores what the business keeps. Test: would the client still care about it in a year, with the whole interface switched off?
Boundary classSits at the edge, translates an actor's request and presents the answer. One per way the outside world talks in — named after who uses it, never after a page.
Control classCoordinates one use case from start to finish. It holds the order of the steps and stores nothing.
The three rooms modelOne use case, three rooms: boundary, control, entity. An actor never walks into the entity room — something translates for them.
AttributeA value you read off one object. “state : String” is a value of one order, not a box. Attributes graduate into classes when they gain identity.
OperationOne responsibility, asked of one object (Order.cancel(reason)) or of a whole collection (Order.findOpenFor(student)). One operation, one responsibility — if the name contains “and”, split it.
AssociationA line saying which class knows which, in a direction you can say out loud: “an order has lines”. This week you draw lines; you do not count them yet.
MultiplicityHow many — 1, 0..*, 1..*. Next week (W07). Do not guess it today, or everything ends up 1..*.
IdentityThe test that separates a class from an attribute: can you point at one and say “that one”? Point at the order — yes. Point at “Accepted” — no, you read it off an order.
TraceabilityEvery class names the specification sentence it came from. No sentence, no class. A class with nothing behind it is padding — delete it.

E · Exercise 6.2 — Draw Your First Domain Model

Draw your domain model in PlantUML — entities, boundaries and controls, plus the associations between them. No multiplicities, no aggregation diamonds, no attributes, no methods — those come later. The AI analysis engine is outside your boundary: it is an external actor, not one of your classes. Source file: docs/diagrams/domain-model-v1.puml.
Four roles, four jobs. Lead keeps the clock and calls the disagreements · Recorder owns the .puml file, and only that file · Reviewer checks every class against a requirement line · Release Manager pushes and confirms the file is in the repo.
Target: eight classes or more, every one traceable to a requirement. A model of five has missed the domain; a model of thirty has drawn the database.
